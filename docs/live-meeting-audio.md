# 로컬 회의 녹음·실시간 미리보기·정밀 전사

구현 대상은 macOS 26 이상 Apple Silicon이다. WorkLogCore의 Linux 공통 빌드는 유지하고 AVFoundation, ScreenCaptureKit, Core ML은 macOS 앱 계층에만 연결한다. 모델 준비는 사용자의 명시적인 다운로드 동작에서만 시작한다.

## 사용자 흐름과 기본값

1. 회의를 선택하고 대면(선택 마이크) 또는 온라인(선택 앱 출력 + 선택 마이크)을 구성한다. 온라인 모드는 앱 목록에서 녹음 범위를 확인한다. 브라우저 회의는 선택한 브라우저 앱의 다른 탭 소리도 포함될 수 있으므로 전용 창/앱을 사용하고 불필요한 탭을 닫는다.
2. 필요한 모델을 각자 명시적으로 준비한다. 준비 없이도 ‘녹음만 시작’이 가능하다. 실시간 모델만 준비해 미리보기를 사용하거나, 정밀 전사와 화자 모델을 나중에 준비할 수 있다.
3. 원본은 CAF PCM으로 저장하고, 저장을 마친 버퍼만 미리보기 경로로 보낸다. 회의 선택·화면 이동과 관계없이 시작 당시 meetingID에 저장한다. 앱 툴바와 메뉴 막대에서도 중지할 수 있다.
4. 중지하면 캡처·원본 파일을 닫고 마지막 미리보기를 최대 8초 기다린 뒤 체크포인트를 저장한다. SDK 연산이 아직 끝나지 않았다면 결과를 무효화하고 종료를 기다려 자원을 해제한다. 이 동안 새 녹음은 원본 저장부터 시작하며 새 추론은 이전 연산이 끝난 뒤 시작한다.
5. 미리 준비된 large-v3와 화자 모델이 모두 있고 자동 정밀 처리가 켜졌다면 large-v3 → unload → SpeakerKit 순서로 처리한다. 모델이 없으면 정밀 전사 대기로 남긴다. 정밀 처리 중 새 녹음은 기존 정밀 작업을 취소하고 원본 녹음을 우선한다. 저장한 구간과 파일은 보존한다.
6. 실시간·정밀·화자 포함·직접 수정 버전을 검토하고 활성 전사본으로 선택한다. 새 인식 결과는 기존 편집을 자동 덮어쓰지 않는다. 타임스탬프를 누르면 해당 트랙의 원본을 재생한다. 화자 이름과 구간 문구를 수정할 수 있다.

| 설정 | 기본값/의미 |
|---|---|
| 실시간 | WhisperKit, 다국어 large-v3-turbo Core ML, `ko`, `transcribe` |
| 갱신/문맥 | 2초마다 시도, 기본 10초(8~12초), overlap 2초 |
| 첫 요청 | 음성 약 0.5초부터 가능; 10초가 찰 때까지 기다리지 않음 |

| 동시 실행 | 전역 1개, 트랙별 최신 대기 1개, 최대 2트랙 순환 |
| 지연 | 최근 추론 시간에 따라 시도 간격을 최대 10초까지 늘림 |
| 종료 후 | large-v3 다국어, 로컬 SpeakerKit, 자동 처리 켬(준비 완료 시) |
| 데이터 | 원본·미리보기 보존, 사용자 수정 자동 덮어쓰기 없음 |
| 개인정보 | localOnly 기본 true, 자동 모델 다운로드/클라우드 대체/전사 텔레메트리 없음 |
| 원본 정리 | 자동 삭제 없음. 보관 기준이 지나도 사용자가 직접 삭제 |

2초는 갱신 시도 간격이며 표시 지연 SLA가 아니다. turbo가 모든 Mac에서 가장 빠르다는 가정도 하지 않는다. 다운로드 파일 크기는 실행 메모리가 아니다. STT는 완전한 축어 전사를 보장하지 않으며 추임새·겹친 발언·개발 용어가 빠지거나 바뀔 수 있다. stablePreview는 실시간 병합의 안정 상태이고 정확도 검증 결과가 아니다.

## 오디오·시간축·복구

병합은 트랙·시간 경계·문맥을 함께 비교한다. SDK segment timestamps를 사용하고 단어 단위 정렬은 제공하지 않는다. 동일 시각·문맥 prefix가 확인된 새 tail은 이전 확정 구간 끝을 임시 경계로 사용한다. 문맥이 바뀐 겹침은 검토가 필요한 partial로 남고 자동 확정하지 않는다. 사용자가 본문/화자를 수정하면 활성 전사에 포함할 수 있다. 240개 화면 캐시는 오래된 확정 구간부터 제외하며 저장소에는 유지한다. 화자 포함 결과도 이 검토 상태를 유지한다.

- 대면 마이크는 AVAudioEngine으로 선택한 장치 UID를 고정한다. 온라인은 ScreenCaptureKit의 선택 앱 PID 필터와 별도 microphone 출력을 사용하고 화면 프레임은 저장하지 않는다. 온라인 마이크도 선택 UID를 고정한다. 마이크 기본 표시는 ‘마이크/현장’이며 자동으로 ‘나’라고 추정하지 않는다.
- 캡처 콜백은 소유 PCM 복사와 제한된 큐 전달만 수행한다. 파일 쓰기·저널은 별도 직렬 큐, 리샘플링·추론은 별도 처리 경로다. 원본 큐는 16MiB/128패킷으로 제한하며 초과·디스크 오류는 정상 녹음 표시를 끝내고 안전하게 중지한다. 미리보기 입력 큐는 최신 4패킷만 유지한다.
- 트랙별 PCM 형식·시작 오프셋·실제 프레임 수·중단 구간을 기록한다. 공통 단조 증가 시계/오디오 타임스탬프로 정규화한다. 중단 시간을 가짜 PCM으로 채우지 않으며 재생·정밀 타임스탬프는 중단 메타데이터를 반영한다.
- 모델 입력만 16kHz 모노로 변환한다. 정밀 전사는 파일 28초 + 이전 2초 문맥, 화자 분리는 최대 120초로 제한한다. 회의 전체 오디오를 한 배열로 읽지 않는다. 화자 특징을 창 사이에 잠정 연결하며 확신이 부족하거나 다른 화자가 겹치면 미확인으로 둔다. 서로 다른 트랙의 동일인을 자동 합치지 않는다.
- 앱 소유 `meeting-recordings/<recordingID>/`의 CAF와 journal을 보관한다. pending → archived 또는 interrupted로 명시 전환한다. 중단 시 CAF의 실제 프레임 수로 복구하고 DB에 다시 연결한다. 손상된 개별 보관 항목 때문에 다른 녹음 복구를 멈추지 않는다. 삭제·export는 경로/일반 파일 검증 후 명시적 동작으로만 실행한다.
- 기존 `meeting-audio` pending은 원본을 새 보관 영역으로 복사한 뒤 이전 pending manifest만 해제한다. 기존 M4A 및 외부 가져오기 파일은 변경·삭제하지 않는다. 자동 재녹음은 없다.
- 잠자기, 입력 제거/교체, 선택 앱 종료, 권한 철회, 포맷/시계 변경을 감지하면 원본을 마무리하고 중지한다. 다른 마이크로 자동 전환하지 않는다. 앱 정상 종료는 비동기 캡처 종료·체크포인트를 기다린다. 저장 실패는 종료를 취소한다.
- 원본 파일 삭제는 전사 저장과 독립적이다. 전사가 성공해도 삭제하지 않는다. 원본을 삭제해도 텍스트 버전과 사용자 편집 이력은 남는다.

헤드셋을 권장한다. 스피커의 원격 음성이 마이크로 다시 들어오는 에코는 두 원본 트랙에 그대로 남는다. 문자열 중복 제거로 에코를 숨기지 않으며 자동 에코 제거 품질을 보장하지 않는다.

## 저장·백업·외부 AI 경계

새 migration v6만 추가한다. v1~v5는 변경하지 않는다. 회의별 recording/track/run/segment/speaker/edit/preview-gap 테이블과 별도 `MeetingAudioStore`를 사용한다. `Meeting.transcript`는 활성 버전 하나의 호환용 본문이므로 검색·텍스트 export에 버전 수만큼 회의가 중복되지 않는다. 직접 전사문을 편집하면 manual 버전으로 보존한다. 확정 구간/3초 체크포인트를 저장하며 자막 갱신마다 전체 회의 목록과 문서를 저장하지 않는다.

기존 회의와 새 회의 모두 `local_only=true`가 기본이다. 원문·회의 메모·연결 메모의 회의 내 사본·인용·요약을 외부 AI로 보내지 않는다. MeetingService에서 입력 구성 전에 검사하고 AIJobRunner의 선택적 preflight로 큐 대기 뒤와 계정 검사 뒤 실행 직전에 재검사한다. 일반 검색/보고/grounded-answer 입력은 회의를 자동 편입하지 않는다. 회귀 테스트는 회의 표식이 이 입력에 들어가지 않고 일반 업무 데이터는 계속 처리되는지 검사한다. 사용자가 회의 밖 일반 메모에 직접 복사한 텍스트까지 추적하는 DLP 기능은 아니다.

로컬 LLM 요약은 구현 범위가 아니다. 로컬 전용 회의에서는 외부 AI 요약을 사용할 수 없다는 안내와 함께 전사·메모·검색·export는 계속 사용할 수 있다. 다른 업무 데이터의 기존 AI 기능은 유지한다. 모델 준비 요청에는 공개 모델 URL만 사용하고 녹음·전사·자격증명을 포함하지 않는다.

DB 백업에는 회의 텍스트·버전·화자·파일 참조가 포함되지만 **오디오 원본과 모델은 포함되지 않는다**. 원본은 회의의 export 기능으로 별도 보관해야 한다. 다른 Mac/과거 백업 복원 후 없는 파일은 `missing`으로 표시하여 조용히 재생 실패로 숨기지 않는다. 기존 DB와 실데이터 삭제는 수행하지 않는다. v6 DB를 이전 앱으로 다운그레이드하기 전에 별도 백업과 텍스트/원본 내보내기가 필요하다.

SDK/API 확인·고정 revision·라이선스 전문 출처는 [meeting-models.md](meeting-models.md)에 있다. 앱 번들에 Argmax LICENSE/NOTICES와 모델 고지를 함께 넣는다.

실제 장치/모델 확인 절차:

1. 사용자가 모델 세 역할을 명시적으로 준비하고 설치 receipt의 ID/revision/digest를 보관한다. 네트워크를 차단한 상태에서 허가된 한국어+영어 개발 용어 음성으로 첫 미리보기와 정밀 전사를 확인한다.
2. 헤드셋 온라인 회의의 지정 앱 출력/마이크 분리, 공통 시점 정렬, 타임스탬프 재생을 확인한다. 다른 앱 알림/다른 브라우저 탭의 포함 범위도 확인한다. 스피커 모드에서는 에코가 원본에 남는지 별도로 비교한다.
3. 회의 화면 이동·다른 회의 선택·한국어 IME 메모 편집 중 녹음 유지, 전역 중지, 중복 중지, 종료 저장 실패를 확인한다.
