# 이슈 #28–#43 통합 검증

2026-10-28 KST. 기록/보고서/검색, TODO, 회의 기능을 별도 worktree에서 병렬 구현한 뒤 통합했다. 원본 main과 기존 작업자의 worktree는 보존한다.

## 통합 경계

- 메모 이력은 신규 migration v10, 회의 메타데이터/수동 요약/업무 출처는 v11, 일반 입력 초안의 제출 확인은 v12에 추가한다. 기존 migration은 변경하지 않는다.
- 일반 입력의 기록 저장과 제출 확인을 같은 DB 트랜잭션으로 기록한다. 저장 직후 체크포인트 파일 교체에 실패해도 재실행에서 이미 제출한 초안을 다시 실행하지 않는다. 상태 변경에 쓰지 않은 본문은 후속 초안으로 복구한다.
- 회의 로컬 검색은 메인 검색과 전역 검색 패널에서 별도 창으로 제공한다. 쿼리/결과/스니펫을 일반 SearchModel이나 grounded-answer 입력에 넣지 않는다. 업무 근거에서 회의·전사 구간으로, 프로젝트에서 관련 회의로 이동한다.
- localOnly 회의에 연결된 업무는 일반 로컬 검색에는 남지만 외부 AI 후보와 제출용/성과 보고서의 업무·진행·상태·계획·보충·승인 메모 근거에서 제외한다. 회의를 휴지통으로 옮기거나 회의 정책을 바꿔도 파생 업무의 기존 보호를 자동 해제하지 않는다. 대기열에서 실행하기 직전에도 정책을 다시 확인한다.

## 회의 아카이브

`.worklogmeeting` 폴더에 버전이 있는 manifest, SHA-256으로 검증하는 records와 선택 원본을 저장한다. 모델 가중치·일반 업무·Secret은 포함하지 않는다. 연결된 프로젝트/태그의 분류 이름은 함께 보존하며 가져올 때 기존 분류와 안전하게 대응한다.

- 내보내기 전에 파일 수·용량·누락 원본을 표시한다. 사용자가 확인한 뒤 원본 상태가 달라지면 다시 확인해야 한다.
- 불완전한 내보내기는 임시 이름만 사용하며 성공한 뒤 최종 이름으로 바꾼다. 취소/실패 시 이번 작업의 임시 파일만 정리한다.
- 가져오기는 파일 해시·크기·누락 목록·상대 경로·심볼릭 링크·용량을 검증한다. 동일 회의는 거절 또는 새 복사로 처리하며 기존 회의를 덮어쓰지 않는다. DB 실패 시 새 오디오 폴더와 새 분류까지 되돌린다.
- 가져온 회의는 localOnly를 유지/강화한다. 원본 재생·재처리는 DB 상대 경로를 검증한 후 읽는다. 일반 DB 백업에 오디오가 없다는 기존 안내와 회의 아카이브의 범위를 백업 화면에서 구분한다.

## 검증 기록

개별 구현·실제 화면 결과는 [기록 검증](record-issues-verification.md), [TODO 검증](todo-issues-verification.md), [회의 검증](meeting-authoring-validation.md)에 기록한다. Core 테스트와 실제 macOS 화면·키보드 검증은 서로 대체하지 않는다.

- 회의 아카이브 14개 테스트: 원본 포함/제외 왕복, 메타데이터·요약 수정 이력, 중복 ID, 손상 해시/누락 목록/경로 탈출/심볼릭 링크, 용량 부족, DB 충돌 롤백, 분류 재매핑, 취소 및 기존 임시 경로 보존 통과.
- AI 대기열 3개 테스트: 대기 중 localOnly가 추가된 업무의 제출용/성과 보고서와 검색 답변은 provider 호출과 AI job 저장 전에 거절함을 확인했다.
- 최종 macOS `swift build --build-tests -j 4` 성공, `swift test --skip-build`: 1,096개, 실패 0개(41.480초). Apple Swift 6.4/Xcode 27.1 SDK를 사용했으며 macOS 26.0 deployment target을 유지한다.
- 최종 네이티브 세션 15개 suite와 PCM 8개 suite 통과. 가짜 데이터의 OAuth identity/loopback, 녹음 복구, 앱 종료 네이티브 검사도 모두 통과했다.
- 보호 정책 전환 5개 회귀: 기존 업무 보호 강화/유지/원자성과 AI 실행 도중 전환 시 응답·fallback의 새 보고서 저장 차단을 확인했다. 이미 외부 전송이 시작된 요청의 입력을 소급 회수할 수는 없다.
- Linux `swift:6.3.3-noble` arm64 컨테이너 전체 테스트 1,096개 통과(85.887초). OCI의 기존 체크아웃·운영 서비스·호스트 패키지는 변경하지 않았다. 격리 컨테이너에만 `libsqlite3-dev`, `pkg-config`를 추가했다. 이미지 digest: `sha256:1038d54c80063f5cdfabc4560990c30af64b5de8ebf28161deb22ca4ad5db866`.
- Linux 최초 실행은 XCTest의 동기 `@MainActor` 함수 변환에서 시작 전에 종료됐다. 신규 테스트의 actor 진입점을 `async`로 맞춘 뒤 전체 실행에 성공했고, 같은 31개 회귀를 macOS에서도 다시 통과했다.
- 배포 manifest/버전 검증 도구 17개 테스트 통과. 배포 인증서/사용자 Keychain 접근 테스트는 로컬에서 실행하지 않았으며 일회용 GitHub CI 경로를 사용한다.

## 운영 반영 경로

배포 대상은 GitHub Releases의 WorkLog 0.15.0 arm64 DMG와 Sparkle latest appcast다. 사용자 Mac의 자격증명이나 기존 저장소를 읽지 않고, 저장소의 `macos-release.yml`이 GitHub-hosted macOS에서 승인된 정확한 merge SHA를 빌드/테스트/서명한다.

PR 및 검증 결과에 대한 통합 승인 후 원본 main을 fast-forward하고 clean·원격 HEAD 일치를 확인한다. `commit=<merge SHA>`, `tag=v0.15.0`, `publish=publish`로 워크플로를 실행한다. 공개 전 DMG/feed 서명·체크섬·업로더 재다운로드 일치, 공개 후 latest feed/manifest/DMG와 앱 updater 로더를 확인한다.

잘못된 배포는 기존 v0.14.0을 latest로 복구해 신규 배포의 자동 업데이트 노출을 중단할 수 있다. 이미 업데이트된 사용자의 앱/DB를 자동으로 다운그레이드하지 않는다. 수정 버전을 배포하거나 사용자가 별도로 승인한 백업 복원 절차를 사용한다.
