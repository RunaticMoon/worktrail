# 회의 녹음·전사 실패 안내와 진단 (0.16.1)

## 확인된 문제와 수정

이슈 #50의 세 코드 결함을 수정한다. 실시간 전사 실패는 안전한 원인·단계·허용된 NSError 숫자 코드를 유지한다. 모델 검증, 토크나이저 준비, Core ML 로딩, 추론을 구분한다. 진단의 `stage`는 미리보기/정밀 전사/화자 분리를, `phase`는 구체적인 실패 지점을 나타낸다. 원문 오류 설명·모델 경로·임의 domain·음성·전사·메모·자격증명은 기록하지 않는다.

실패한 입력의 오류 표시는 성능 정보, gap, 종료 시 자막 갱신, 다른 입력의 성공으로 지워지지 않는다. 같은 입력의 실제 추론 성공 뒤 해제된다. 동일한 실패가 계속되면 진단을 반복 기록하지 않으며, 회복 후 다시 실패하면 새 이벤트를 남긴다. 원본 녹음은 기존대로 독립 보관한다.

녹음 시작 실패는 권한 설명 누락, 마이크 권한, 화면/시스템 오디오 권한, 마이크 없음, 선택 앱 없음, 형식 오류, 진행 중인 작업을 구분한다. 정리 과정에서 반환하는 원본 상태도 구체적 시작 안내를 덮어쓰지 않는다.

정밀 전사 첫 단계 실패에는 모델 준비/정밀 전사 재실행을 안내한다. 화자 분리 실패에는 이번 처리에서 저장한 완료 전사의 상태, 원본 해시, 모델, 설정, revision, 사용자 수정 여부를 다시 확인한 경우에만 화자 분리 재시도를 안내한다. 이전 완료본이 있다는 이유만으로 재사용할 수 있다고 안내하지 않는다. 취소는 실패와 구분하며 기존 원본·전사·수정본·메모를 보존한다.

## 사용자 증상과 아직 확인되지 않은 사항

2026-10-29 KST 사용자 답변은 “1.5.0 버전”, “마이크가 변경되었다”는 안내와 녹음 시작/유지 단계 실패다. 저장소의 v0.15.0은 AVAudioEngine 구성 알림을 받으면 실제 입력 변경 여부를 검사하지 않고 해당 안내로 중단했다. 이 경로는 #49/v0.16.0에서 동일 입력 알림 무시와 제한된 엔진 재시작으로 수정됐다.

사용자가 말한 1.5.0과 저장소 v0.15.0의 동일성, 설치 바이너리, 실제 이벤트 리포트는 확인되지 않았다. 증상은 이전 알림 오인 경로와 부합하지만 사용자 장애의 직접 원인 확정이나 v0.16.0 회귀 재현으로 기록하지 않는다. 이번 작업에서 마이크 정책을 추가 변경하지 않았다.

개발 M1의 `/Applications`, 사용자 `Applications`에는 WorkLog 설치 앱이 없고 기본 진단 디렉터리도 없었다. 실제 사용자 마이크와 모델을 실행하지 않았다. 실제 Mac에서 60초 이상 녹음 → 한국어 실시간 전사 → 중지 → 정밀 전사 → 저장·재열기는 남은 수용 검증이며 #50을 자동으로 닫지 않는다.

## 배포와 롤백

PR 승인 뒤 merge → M1 원본 main fast-forward/clean/원격 HEAD 대조 → 해당 merge SHA로 `macos-release.yml`을 `tag=v0.16.1`, `publish=publish`로 실행한다. 운영 대상은 GitHub Releases의 arm64 DMG와 Sparkle 업데이트 피드다. 기존 workflow의 고정 앱 서명, DMG/feed 서명, 재다운로드 manifest 검증을 사용한다. 승인 전에는 공개·설치하지 않는다.

서명된 바이너리는 merge SHA에서 CI가 생성하므로 승인 전 체크섬은 없다. 배포 시 manifest source SHA·앱 버전·DMG SHA256·고정 서명을 대조하고 공개 피드를 확인한다. 이전 v0.16.0 자산을 보존한다. 문제 발생 시 v0.16.0을 최신 릴리스로 되돌려 추가 배포를 멈춘다. 이미 설치된 앱은 자동 다운그레이드하지 않으며 필요한 경우 보존된 DMG로 재설치한다. DB migration은 없다.
