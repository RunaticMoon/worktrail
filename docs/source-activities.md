# GitHub·Jira 기록 분리 — 0.14.0

수집 기록을 일반 메모로 나열하던 날짜 화면을 출처별 목록으로 바꾼다. `활동 기록 / 업무 상태 / 메모 / GitHub / Jira`에서 각각 개수를 확인한다. 전체 활동에도 출처별 아이콘과 간결한 행을 사용한다. 기존 ⌘⌥1–3을 유지하고 GitHub/Jira에 ⌘⌥4/5를 추가하며 Ctrl-Tab 순환과 방향키·Return·Esc 왕복을 지원한다.

GitHub는 `조직/저장소 · PR #77 · merged` 또는 브랜치·push를 표시한다. Jira는 `PROJECT-77 · Open → Done`처럼 이슈 키와 상태 전환을 우선하고, 이슈 생성·기타 변경·작업 시간 기록도 구분한다. 긴 설명은 상세에 보관하고 원본 링크와 기존 편집·업무 연결을 제공한다. API에 없는 병합 상태나 커밋 수는 만들어내지 않는다.

## 저장과 호환

- 분류의 기준은 `imported_activity.source`와 `memo_id`이다. 사용자가 직접 쓴 `[GitHub Enterprise]` 문자열은 분류 근거가 아니다.
- 원문 저장은 기존 memo 행을 내부 backing record로 유지한다. 별도 테이블로 본문을 옮기거나 삭제하지 않으므로 수정 이력·프로젝트/태그·업무 연결·기존 `memo:<id>` 보고서 인용·백업 참조를 보존한다. 일반 메모 조회에서는 수집 기록을 제외하며 출처 전용 읽기 모델로 제공한다.
- WorkSchema v9는 선택적인 `display_json`과 조회 인덱스만 추가한다. 새 수집은 API 필드에서 표시 정보를 저장한다. 기존 기록은 알려진 이전 포맷과 원본 URL에서 보수적으로 복원하며, 재수집 시 비어 있는 표시 정보만 채운다. 본문 수정이나 휴지통 상태를 덮어쓰지 않는다.
- 검색은 GitHub/Jira 유형을 구분하고 구버전 memo 색인을 복구한다. 프로젝트·태그 필터와 기존 원문 이동을 유지한다.
- 보고서에는 각 원문을 한 번만 포함하고 GitHub/Jira 근거 종류를 구분한다. 저장된 인용 ID와 승인된 업무 연결은 유지한다. 수집 결과로 업무 상태·완료 건수를 자동 변경하지 않는다.
- 수집 주기·자격증명·네트워크 정책은 기존과 같다. 실제 자격증명이나 사용자 DB를 개발 검증에 사용하지 않는다.

## 배포와 복구

PR 승인 후 M1 원본 main을 동기화하고 정확한 merge SHA로 기존 `macos-release.yml`에서 v0.14.0을 빌드·서명·배포한다. 배포 전에 CI와 DMG를 검증하고 배포 후 공개 파일의 해시·서명·Sparkle feed·로더를 확인한다. v0.13.1 릴리즈와 업데이트 전 데이터 백업을 보존한다. 롤백 시 feed/latest를 이전 릴리즈로 복구하며, v9 DB를 사용하는 앱을 자동 다운그레이드하거나 사용자 데이터를 자동 복원하지 않는다.

## 검증

2026-10-28에 다음 검증을 완료했다. 모두 가짜 데이터로 실행했으며 실제 회사 API나 사용자 데이터는 사용하지 않았다.

- macOS SDK 27 / Swift 6.4: `swift build --build-tests`, 전체 1,033개 테스트 통과.
- Linux aarch64 / Swift 6.3.3: 동일 Core·Tests 소스로 전체 1,033개 테스트 통과.
- 핵심 회귀 검사: v8 업그레이드, 메모/출처 분리·KST 날짜·중복 방지, 편집/삭제 보존, 구조화된 API/이전 기록 표시, 검색 필터/재색인, 보고서 근거·승인된 업무 연결 보존.
- macOS 네이티브 화면·키보드 검사: many fixture 25개, empty fixture 8개 통과. 출처별 개수·간결한 행·5개 영역 이동·방향키·Return 상세·Esc 선택 복귀·전체 본문·원본 링크·편집 동작 표시를 확인했다.
- 로컬 v0.14.0 DMG 생성 및 `distribution/verify-dmg.sh` 통과. arm64·최소 OS·서명 구조·Sparkle 로더를 검증했다. 로컬 ad-hoc 서명본은 공개하지 않으며, 승인 후 CI가 고정 인증서로 다시 빌드·서명한다.

실제 GitHub Enterprise/Jira 계정의 새 표시 정보 수집과 운영 배포 후 동작은 이 로컬 검증에 포함되지 않는다. 공개 산출물의 해시·서명·feed 검증은 승인 후 수행한다.
