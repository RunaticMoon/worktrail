# 통합 회의 탐색·아카이브 UI 검증

검증 시각: 2026-10-28 20:56 KST. 통합 worktree의 최신 Debug `WorkLogApp`을 별도 임시 앱에 복사하여 실행했다. 최종 검증 소스 HEAD는 `7a33b6a9a4aef6cfb8ef97ec43be95617fd06643`이며 검증 중 발견한 창 재사용·업무 근거 표시 수정이 포함된 빌드를 다시 실행했다. 소스 코드는 이 검증 작업에서 수정하지 않았다.

## 환경과 격리

- Apple M1 Max, macOS 네이티브 SwiftUI/AppKit, 창 1180×800.
- 별도 bundle `dev.worklog.IntegrationReview`, 실행 인자 `--ui-test-fixture many`. 각 입력 전에 정확히 한 개의 해당 bundle, 실행 인자, 대상 PID, 전면 앱을 확인했다.
- 앱이 생성한 `WorkLog-UI-many-*` 임시 저장소와 가짜 인증만 사용했다. 실제 업무 데이터·계정·Keychain·모델·마이크·AI 호출은 사용하지 않았다.
- 원본 Debug 실행 파일 SHA-256: `163c03b95b9f20ef5042c430e655f6c28dce63cc67593e64210233f1434c2366`.
- 별도 bundle ad hoc 서명 후 실행 파일 SHA-256: `823c3549f6cf4c08a0792ca0874b1e04e58929338671ca0dee87978e112ae6df`. 서명 때문에 원본 Debug 파일 해시와 다르다.
- 네이티브 AX 조작과 키보드 입력을 사용했다. 편집기의 AX 포커스가 실제 입력 포커스로 이어지지 않을 때는 해당 검증 창 안의 편집기 좌표로 포인터 포커스를 보완했다. 전 구간 키보드 전용 검증은 아니다.

## 통과한 경로

| 경로 | 실제 확인한 결과 |
|---|---|
| 주 검색 화면 → 회의(로컬) | 합성 회의명 입력, 검색 결과 선택, 해당 회의 제목·메모 화면으로 이동 |
| 전역 검색 패널 → 회의(로컬) | ⌘F 패널에서 검색 후 해당 회의로 이동, 검색 패널 닫힘 |
| 기존 주 창 재사용 | 주 검색·전역 검색을 반복한 뒤 AX 표준창 1개 유지 |
| 회의 메모 → 업무 검토·확정 | 합성 근거를 검토하여 새 업무 생성, 미지정 담당자 유지 |
| 업무 상세의 회의 근거 | `회의 근거 (1)`, 연결 당시 문장, 로컬 전용 근거·외부 AI/보고서 제외 안내 표시 |
| 업무 근거 → 원회의 | 회의명 버튼 실행 후 업무 상세 닫힘, 해당 회의로 이동, 주 창 1개 유지 |
| 아카이브 미리보기 | 원본 음성 포함 해제 후 `텍스트만 · 음성 0개`와 용량 표시, 저장 버튼 활성화 |
| 네이티브 파일 대화상자 왕복 | NSSavePanel로 `/tmp`의 합성 `.worklogmeeting` 폴더 저장, NSOpenPanel로 같은 폴더 선택 |
| 새 복사본 가져오기 | UI의 새 복사본 옵션으로 가져오기 성공, 외부 AI 불허 안내 표시 |
| 저장소 확인 | 해당 PID가 연 임시 DB만 read-only 확인: 서로 다른 회의 ID 두 개, 제목·전사·메모 일치, 두 회의 모두 `local_only=1`, 기존 업무 근거 링크 유지 |

내보낸 폴더는 `manifest.json`과 `records.json`만 포함했다. 결과 JSON과 AX 관측 자료는 `/tmp/worktrail-integration-ui-result.json`, `/tmp/worktrail-integration-*-dump.json`에 남겼다. 테스트 산출물에는 합성 데이터만 있다.

## 발견 후 재검증한 결함

- 최초 빌드에서 검색으로 회의를 열 때 표준창이 1→2→3개로 늘었다. 통합 담당자가 기존 주 창을 찾아 재사용하도록 수정했고, 새 bundle의 새 fixture에서 반복 이동 후 1개 유지로 재검증했다.
- 최초 빌드에서 DB에 업무 근거 링크가 저장되어 있어도 상세 화면에 나타나지 않았다. 빈 `Group`의 `.task` 대신 실제 컨테이너를 사용한 수정 후 근거 표시와 역링크 이동을 재검증했다.
- 화면을 닫거나 전환하는 버튼의 AXPress가 노드 소멸 때문에 오류를 반환하는 경우가 있었다. 해당 입력의 성공은 반환 코드가 아니라 이후 목적지·sheet 닫힘·창 개수를 별도로 확인하여 판정했다. 이를 앱 저장 실패로 세지 않았다.

## 미검증 및 범위

- 프로젝트의 연결 회의 버튼과 기존 기간·태그·휴지통 조건 초기화는 이번 최종 GUI 검증에 포함하지 않았다. 초기 빌드에서 메타데이터 프로젝트 선택·저장까지만 조작했으며 최종 빌드의 전체 이동 경로 통과로 주장하지 않는다.
- 음성 포함 아카이브, 실제 녹음·전사·화자 분리, 구간 타임스탬프 검색 이동은 이 텍스트 fixture로 검증하지 않았다. 해당 Core/가짜 PCM harness 결과와 구분한다.
- 한글 IME 조합, VoiceOver 낭독, 작은 창에서 전역 검색·아카이브 sheet 배치는 이번 검증 범위 밖이다.
- 실제 운영 앱과 데이터에는 접근하거나 배포하지 않았다. 운영 적용 판단은 통합 PR의 검증·승인 절차를 따른다.
