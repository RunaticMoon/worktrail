# 제품 요구사항 — Mac 업무 기록 앱

버전 1.0 · 2026-10-01 · 제품명 미정 (`WorkLog`는 임시 코드명)

## 0. 목적과 범위

업무 도중 확인한 사항·진행·완료 내용을 놓치지 않고 짧게 기록한다. 기록을 다시 찾아 주간보고를 작성하는 수고를 줄이고, 연말에 프로젝트별 기여와 성과를 복원할 수 있게 한다. 설정값은 빠르게 저장·검색·부분 수정·복사한다.

**대상:** 본인이 사용하는 한 대의 Mac. 한국어 UI와 키보드 중심 입력. 직접 타이핑이 기본이다.

**첫 버전의 완료 범위:** Memo·Task·Secret 입력, 날짜별 조회, 프로젝트와 계획, 원문 검색·명시적 AI 질문, 두 계열의 보고서, 성과 보충 질문, Codex 스킬 연결, 로컬 백업과 복원. 단계적 개발은 허용하지만 마지막 MVP에서 이 범위를 몰래 빼지 않는다.

**향후:** Task에 연결된 GitHub PR·Jira 이슈 읽기, 이후 별도 승인된 Jira 쓰기 연동.

**범위 밖:** 다중 기기 동기화, 모바일·웹 앱, 협업 서버, 자동 음성·화면 수집, 브라우저 선택 내용 자동 캡처, 전체 문서 크롤링, Secret AI 처리, 로컬 LLM, 자동 외부 보고서 게시.

## 1. 용어와 데이터의 책임

| 용어 | 의미 |
|---|---|
| Memo | 생각, 이야기 나눈 내용, 확인한 사실 등을 남기는 제목 없는 기록 |
| Task | 예정부터 진행·보류·완료·취소까지 이어지는 하나의 전역 업무 |
| 진행 기록 | 특정 업무일에 Task에서 한 일·확인한 사항·근거 링크 |
| 프로젝트 적용 | 하나의 Task가 각 프로젝트에 적용되는 상황과 상태 |
| Daily box | 특정 날짜의 원문과 당시 상태를 모아 보는 화면. 원본 복제 저장소가 아님 |
| 이번 주 계획 | 특정 주에 수행하기로 사용자가 확정한 범위. 실제 상태와 독립적 |
| 제출용 주간보고 | 지난주 업무와 이번 주 계획을 팀 양식으로 간략히 보고하는 문서 |
| 성과 리포트 | Daily·Weekly·Monthly·Quarterly·Yearly 상세 근거 자료 |
| Secret | 제목·그룹과 key/value 표를 가진 로컬 암호화 보관 항목 |
| 스킬 | 사용자가 기존 Codex에서 사용하는 작업 지침·참고 자료 |

**공통 원칙:** 원문, 구조화된 상태, AI 해석, 사용자 확정 문서를 분리한다. AI는 원문을 삭제하거나 상태를 임의 변경하지 않는다.

## 2. 빠른 입력과 키보드 UX

### CAP-01. 전역 입력과 검색

입력 핫키와 검색 핫키를 다르게 제공하고 모두 설정에서 변경 가능하게 한다. 기본 입력 유형은 **Memo**이며 설정에서 Task·Secret 등으로 바꿀 수 있다. 마지막 사용 유형이 기본 설정을 몰래 덮어쓰지 않는다.

핫키 충돌을 감지하거나 등록 실패를 안내한다. 앱이 다른 앱 뒤에 있어도 입력창을 열고, 저장 후 이전 앱으로 돌아간다. 구체적인 초기 키 조합은 제품 확정사항이 아니며 설정 가능하게 구현한다.

### CAP-02. 작성 동작 — 제안 기본값

- Enter: 본문 줄바꿈. ⌘Enter: 저장하고 닫기. Esc: 초안을 보존하고 닫기.
- 입력 저장은 네트워크·AI·백업 작업 완료를 기다리지 않는다.
- Secret 초안은 일반 초안·로그에 섞지 않는다. 암호화 가능한 잠금 해제 상태에서만 보존한다.
- Secret 표에서는 Tab으로 셀 이동, 행 추가·삭제, 키보드 복사·편집을 지원한다. 저장 단축키는 동일하다.

### CAP-03. 실제 업무일

기록한 시각과 실제 업무일을 별도로 저장한다. 업무일 기본값은 오늘이고 입력창에서 변경 가능하다. 늦게 작성한 기록은 선택한 실제 업무일의 타임라인·리포트 근거로 들어간다.

과거 날짜 화면 자체는 당시 상태를 조회하는 용도다. 과거 화면의 상태를 직접 수정하는 UI를 기본으로 삼지 않는다. 수정·보충이 필요하면 현재 입력창에서 업무일과 대상을 지정해 새 이력으로 남긴다.

## 3. Memo

### MEM-01. 제목 없는 원문

본문만 작성해 저장할 수 있다. 첫 줄은 목록 미리보기로 사용하며 별도 제목 작성을 요구하지 않는다. 프로젝트·태그는 선택 사항이다. 입력한 원문은 AI 요약과 독립적으로 보존한다.

### MEM-02. Task 연결 제안

AI가 Memo와 관련 Task의 연결을 제안하고 사용자가 승인·거절·나중에를 선택한다. 승인된 연결을 Task의 맥락·성과 근거로 활용한다. 연결해도 Memo 원문을 이동·삭제하지 않는다.

Memo를 연결했다고 새 Task를 자동 생성하거나 업무를 완료 처리하지 않는다. 이야기나 아이디어를 실현된 성과로 바꾸지 않는다. 일반 Daily 정리에는 그날 Memo 자체를 활용할 수 있지만, 특정 Task의 확정 성과 근거로 연결하려면 승인 여부를 확인한다.

**링크:** Memo 안의 URL은 저장·열기만 한다. Task 연결을 승인해도 Memo 안의 URL을 자동 수집하지 않는다.

## 4. Task: 전역 원본과 이력

### TASK-01. 기본 속성

업무명, 상태, 실제 시작일(알 수 없으면 비어 있음), 완료 이력, 마감일, 하위 체크리스트, 진행 기록, 링크, 여러 프로젝트, 검색 태그를 지원한다. 업무명 이외의 선택 속성을 강제로 채우게 하지 않는다.

새 Task를 완료 상태로 바로 등록할 수 있다. 시작일을 모르는 완료 업무는 시작일을 추정하지 않는다. 기존 Task를 찾아 진행 또는 완료 기록을 붙일 수 있다.

### TASK-02. 상태

| 상태 | 의미 |
|---|---|
| 예정 | 아직 실제로 시작하지 않은 업무 |
| 진행 | 실제 진행 중인 업무 |
| 보류 | 다시 수행할 가능성이 있으나 중단한 업무 |
| 완료 | 사용자가 전체 완료를 직접 확정한 업무 |
| 취소 | 더 진행하지 않기로 한 업무 |

재개는 별도 상태가 아니라 보류·완료 등에서 진행으로 바뀌는 사건이다. 보류·취소 사유는 선택 메모로 남길 수 있다. 취소된 업무라도 이미 수행한 활동은 유지한다.

취소·보류에서 돌아오는 전환 역시 이력으로 관리한다. 모든 허용 전환은 테스트 가능한 규칙으로 정의하고 불가능한 시간순 모순을 사용자에게 알려야 한다.

### TASK-03. 전체 완료는 수동

프로젝트 적용이나 모든 체크리스트가 완료돼도 전체 Task는 자동 완료하지 않는다. 사용자가 전체 완료를 선택할 때 남은 항목을 보여주고 확인한다. 미완료 항목을 자동으로 완료 처리하거나 날짜를 만들어 넣지 않는다.

일부 프로젝트가 취소된 상태여도 사용자가 나머지 범위를 완료했다고 확정할 수 있다. 취소 이력은 그대로 남긴다. 완료 전에 범위가 남아 있다는 경고는 허용하지만 업무 종료를 영원히 막는 것은 아니다.

### TASK-04. 재개와 새로운 업무

기존 완료 범위의 누락·후속 수정은 같은 Task를 재개한다. 새로운 요구사항·별도 개선은 새 Task를 만들고 이전 Task와 관련 관계로 연결한다.

재개하더라도 이전 완료일과 당시 기록을 삭제하지 않는다. 다시 완료했을 때 전체 고유 업무 건수는 하나이며, 완료 사건은 여러 개일 수 있다. 기간별 보고에는 해당 기간의 추가 활동을 정확하게 표현한다.

### TASK-05. 진행 기록

기록에는 본문, 실제 업무일, 기록 시각, 관련 프로젝트(0개 이상), 관련 체크리스트(선택), 링크, 상태 변경 사건을 연결한다.

프로젝트를 고르지 않은 기록은 **Task 공통 기록**이다. 공통 기록 추가와 모든 프로젝트 상태 일괄 변경은 다른 명령이다. 한 기록이 여러 프로젝트에 해당하면 연결은 여러 개지만 활동 원본은 하나다.

### TASK-06. 하위 체크리스트

독립된 하위 Task 계층 대신 한 단계 체크리스트를 제공한다. 항목별 완료 이력과 선택적인 관련 프로젝트를 둘 수 있다. 체크리스트 완료와 프로젝트 적용 완료를 동일한 사실로 간주하지 않는다.

체크리스트 전체 완료도 Task 전체 완료를 유발하지 않는다. 상태를 연결해서 변경해야 한다면 별도의 명시적 사용자 행동으로 처리한다.

## 5. 프로젝트와 태그

### PROJ-01. 입력

프로젝트는 `@`, 검색 태그는 `#`으로 검색·선택한다. 공백을 포함하는 프로젝트 이름도 자동완성의 하나의 항목으로 선택한다. 이름이 아니라 안정적인 ID로 연결한다.

### PROJ-02. 다중 프로젝트

한 Task가 G·J·K에 영향을 주면 동일한 Task에 세 프로젝트를 연결한다. 대표 프로젝트 하나를 필수로 강제하지 않는다.

전체 Task 목록과 날짜별 활동에는 원본을 한 번 표시한다. 프로젝트 화면에서는 동일 원본을 각각 참조한다. 전체 업무 건수는 Task ID의 distinct 집계다. 프로젝트별 연관 건수와 전체 건수는 다른 지표로 표시한다.

### PROJ-03. 선택적인 프로젝트별 적용 상태

단순 연결만 필요한 Task와 프로젝트별 예정·진행·보류·완료·취소 관리가 필요한 Task를 구분한다. 후자는 G 완료 / J 진행 / K 예정 같은 상태를 유지한다.

프로젝트별 시작·완료·보류·취소와 진행 기록을 각각 남길 수 있다. 특정 프로젝트를 완료해도 다른 프로젝트나 전체 Task는 자동 변경되지 않는다.

연결이나 명칭을 나중에 수정해도 이미 확정한 보고서의 표기·근거 스냅샷은 유지한다. 과거 연결을 통째로 새 프로젝트로 바꾸지 않는다.

## 6. 날짜별 화면과 시간 규칙

### DAY-01. 기본 3열

| 영역 | 내용 |
|---|---|
| 타임라인 | 해당 실제 업무일의 Memo·Task 생성/시작·진행 기록·부분 완료·전체 완료 등 |
| Task | 해당 날짜의 예정·진행 업무와 그날 시작·완료 표시, 필요 시 보류·취소 필터 |
| Memo 정리 | Memo 원문 목록과 그날 AI 정리. 마지막 생성 시점을 구분 표시 |

전체 Task 화면은 현재 업무 관리용이다. 과거 날짜 화면은 당시 상태 조회용이다. 진행 상태지만 그날 활동이 없는 업무는 Task 영역에 보이되 타임라인에 가짜 활동을 만들지 않는다.

오늘 화면은 현재까지의 상태, 마감된 날짜는 해당 날짜 종료 상태를 사용한다. 같은 날 시작·완료되면 두 사건 모두 남기되 고유 완료 업무는 하나다.

### DAY-02. 달력 경계

시간대는 기본 `Asia/Seoul`, 하루는 자정부터 다음 자정 직전까지다. 구현은 끝 경계를 제외하는 `[start, end)` 구간을 사용한다. 월~일은 ISO 형태의 월요일 시작 주로 처리한다.

날짜만 알려진 활동에 정확한 시간을 임의로 붙여 표시하지 않는다. 같은 날 사건 순서를 안정적으로 관리하고, 필요하면 보충 입력에서 실제 순서를 지정한다. 늦은 입력은 단순 저장 순서가 아니라 실제 업무일과 사건 순서로 상태를 재구성한다.

### DAY-03. 늦은 입력과 변경

원본 이력을 추가하면 영향받는 날짜의 재생 가능한 상태·초안 캐시를 갱신할 수 있다. 이는 확정 보고서를 덮어쓰는 것과 다르다. 확정본에는 당시 생성에 사용한 원문 버전과 상태를 보존하고 변경 알림을 제공한다.

## 7. 이번 주 계획

### PLAN-01. 후보 → 확인 → 확정

지난주 미완료 업무·이번 주 마감 업무 등을 후보로 제안한다. 후보는 확정 계획이 아니며 사용자 확인 전에 보고서의 ‘예정’에 들어가지 않는다.

보류·취소 업무를 자동으로 진행 계획으로 되살리지 않는다. 사용자가 의도적으로 선택하는 경우에도 계획 포함과 실제 상태 전환은 분리한다.

### PLAN-02. 선택 단위

Task 전체, 특정 프로젝트 적용, 특정 체크리스트 단위를 선택할 수 있다. 공통 문서 정리처럼 프로젝트를 지정하지 않는 체크리스트도 포함한다.

Task 전체와 그 안의 항목을 동시에 고르면 보고서에서 중복되지 않도록 정규화한다. 선택한 세부 문구를 잃지 않되 같은 범위를 두 번 계산하지 않는다.

### PLAN-03. 상태와 분리

계획 확정은 착수·완료·실적이 아니다. 시작일·상태를 자동 변경하거나 Task를 복제하지 않는다. 주간보고의 지난주 상태와 이번 주 계획을 서로 다른 기간 데이터로 구성한다.

## 8. 제출용 주간보고

### WEEK-01. 목적과 기간

월요일에 간략한 팀 제출 문서를 만든다.

- 완료·진행: 지난 월요일부터 일요일까지의 활동과 **일요일 종료 상태**.
- 예정: 이번 월요일부터 일요일 사이에 수행할 **사용자 확정 계획**.
- 일요일 진행, 월요일 오전 완료인 업무는 지난주 상태를 ‘완료’로 바꾸지 않는다.

예: 2026-10-05 월요일 보고는 과거 `[2026-09-28, 2026-10-05)`와 계획 `[2026-10-05, 2026-10-12)`를 분리한다.

### WEEK-02. 사용자 제공 초기 양식

```text
대중교통 길찾기
완료 Java 자동 포맷팅 도입 및 전체 코드 포맷 적용
완료 품질 테스트 도구에 PC 대중교통 미들 응답 포맷 지원 추가
완료 품질 테스트 도구의 Gradle 의존성·플러그인 저장소를 사내 Nexus3 우선 사용으로 변경
진행 지하철 데이터 미사용 배포 스크립트 정리 및 빌드·배포 문서화
진행 게이트필터 도구의 HTTPS 접속 시 지도 미표시 수정
예정 시간표 길찾기 가이드 개선 논의 — wade.lim과 협의

기타
완료 OpenViking 이미지 v0.4.21 업데이트 변경 머지
```

이는 출력 양식의 예시이지 모든 사용자의 실제 Task를 자동 생성하라는 뜻이 아니다. 제출용 문장에는 장황한 회고·미확인 수치·중복 근거를 기본으로 덧붙이지 않는다. 원문·링크 근거는 앱 내부에서 연결한다.

### WEEK-03. 공통 업무 중복 방지

다중 프로젝트 Task는 공통 업무 제목 아래 한 번만 작성한다.

```text
공통 인프라
진행 공통 인프라 설정 개선 — G 적용 완료, J 검증 중
예정 공통 인프라 설정 개선 — J 적용 마무리 및 운영 문서 정리
```

공통 업무는 보고서 출력용 묶음이며 데이터상 별도 프로젝트를 강제하지 않는다. 완료·진행·예정이 다른 기간과 목적을 나타내므로 지난주 진행과 이번 주 예정은 함께 나올 수 있다.

### WEEK-04. 프롬프트·확정

템플릿 이름, 프롬프트, 출력 예시, 버전, 선택 스킬을 관리한다. 팀이 바뀌면 복제해서 새 템플릿을 만든다. 템플릿 수정은 과거 확정본에 소급하지 않는다.

미리보기에서 문장 수정, 업무 포함/제외, 이번 주 계획 확정을 제공한다. 첫 버전의 제출 수단은 텍스트 복사다. 자동 게시를 하지 않는다.

**제안 기본값:** 보고 주의 완료 사건이 있고 일요일 종료 상태가 완료인 업무는 ‘완료’, 일요일 종료 상태가 진행인 업무는 ‘진행’ 후보로 분류한다. 기간 안에 완료 후 재개됐으면 최종 상태와 재개 사실을 반영한다. 보류·취소는 세 가지 제출 표기 중 하나로 거짓 변환하지 않고 검토 화면의 제외/변경 항목에 따로 보여주며, 팀 템플릿에서 추가 표기를 설정할 수 있다. 상세 성과 리포트에는 이력을 유지한다.

## 9. 성과 축적용 리포트

### PERF-01. 다섯 단계와 근거

| 종류 | 목적·기본 집계 |
|---|---|
| Daily | 하루의 실제 활동, 상태, 진행 기록, Memo 맥락 |
| Weekly | 월~일의 상세 수행 내용, 의사결정, 결과·미완료·근거 |
| Monthly | 그달 업무를 정리하는 중간 성과 자료 |
| Quarterly | 3개월의 월간 자료와 원본을 묶은 수행 내역 |
| Yearly | 평가 기간의 프로젝트별 기여·결과·근거를 정리한 자료 |

월간은 달력 월, 분기는 1~3/4~6/7~9/10~12월을 제안 기본값으로 둔다. 리포트 생성 시점은 기간 종료 후 첫 실행을 기본으로 한다. 상위 리포트는 하위 리포트를 사용하지만 Task ID·원문·활동의 실제 날짜를 다시 확인한다.

주간이 월을 가로지른다고 주간보고 전체를 두 달에 복제하지 않는다. 평가 종료일이 월중이라면 월간 리포트 전체를 무조건 넣지 않고 종료일까지의 근거만 쓴다.

### PERF-02. 상세 내용

수행 업무, 문제·배경, 본인 담당 범위, 주요 판단, 프로젝트별 적용 과정, 확인된 결과·효과, 남은 일, 근거 링크를 기록된 범위에서 정리한다.

원문에 없는 정량 성과·기여율·비용 절감·영향 범위를 만들어내지 않는다. 단순 ‘진행 중’은 실제 작업한 날의 횟수나 노동시간이 아니다. Memo의 논의와 실제 실행을 구분한다.

프로젝트별 같은 Task를 참조할 수 있지만 전체 업무 수는 중복 집계하지 않는다. 프로젝트별 효과는 해당 프로젝트의 근거가 있어야 한다.

### PERF-03. 평가 기간

첫 평가 리포트는 시작일을 지정한다. 그다음은 직전 **확정 평가 리포트** 종료일 다음 날이 기본 시작일이다. 이번 종료일은 사용자가 지정한다. 보고서 생성일과 집계 종료일은 별개다.

같은 평가 기간의 새 버전을 만들었다고 다음 평가 시작일이 또 이동하지 않게 한다. 평가 기간 ID와 리포트 버전 ID를 분리한다. 경계를 변경하는 기능은 중복·누락을 경고한다.

### PERF-04. 초안과 확정본

초안 생성, 수동 편집, 확정, 새 버전 생성, 원본 변경 알림을 제공한다. 자동 작업은 확정본을 덮어쓰지 않는다. 수동 편집 중인 초안도 자동으로 손실시키지 않고 변경 제안 또는 새 초안을 만든다.

각 버전은 기간·시각·원본 revision·Task ID·프롬프트 버전·스킬 식별자·AI 모델 정보(제공된 경우)를 보존한다. 날짜와 상태를 LLM이 결정하지 않는다.

### PERF-05. 마감과 재시도

자정에 전날 Daily를 생성한다. 앱이 실행 중이 아니거나 절전·오프라인이면 실제 실행 가능 시 누락된 작업을 생성한다. 동일 기간 작업은 중복 실행·중복 저장하지 않는다. AI 실패는 기록 저장과 검색을 막지 않는다.

원문 변화가 없는 기간의 재생성은 불필요한 AI 요청을 줄인다. 기록 없는 날짜는 ‘기록 없음’과 실제 진행 상태만 앱에서 표시하고 성과를 만들어내지 않는다.

## 10. 성과 보충 질문

### QUIZ-01. 월요일 검토와 함께

제출용 주간보고 준비 알림·검토 화면에서 부족한 성과 근거를 짧은 질문 카드로 제시한다. 문제 해결 이유, 확인한 결과, 본인의 역할처럼 기록에 빠진 중요한 내용을 묻는다.

답변·확인한 결과 없음·나중에·이 질문 제외를 지원한다. 제안 기본값은 한 번에 중요한 질문 최대 3개다. 질문은 점수나 정답 맞히기가 아니라 기억 보완용이다.

### QUIZ-02. 기록과 제출 분리

답변하지 않아도 주간보고를 복사·확정할 수 있다. 답변은 해당 Task의 성과 근거 보충으로 저장하며, 입력한 날짜와 설명 대상 업무 기간을 따로 남긴다.

월요일에 지난주 작업의 효과를 설명했다고 월요일 새 업무 실적으로 집계하지 않는다. 이미 답한 질문을 같은 근거에서 반복 생성하지 않는다. 상세 리포트의 초안·새 버전에 반영하되 확정본은 보존한다.

## 11. 검색과 회사 AI

### SEARCH-01. 즉시 원문 검색

Memo, Task 업무명·진행 기록, 상세 리포트, 프로젝트·태그를 로컬 인덱스로 찾는다. 최근 저장한 기록이 검색에 반영되어야 한다. 유형·프로젝트·태그·기간 필터와 원문 이동을 제공한다.

Secret 제목은 별도 로컬 영역에서 검색할 수 있다. Secret의 본문·이전 값은 일반 검색 인덱스·AI 검색 컨텍스트에 넣지 않는다.

### SEARCH-02. 명시적인 자연어 답변

검색 결과가 먼저이고 AI 답변은 사용자가 명시적으로 실행한다. 질문에 관련된 일반 기록을 찾아 근거를 표시한 답을 만든다. 근거가 부족하면 그 한계를 알리고 없는 내용을 채우지 않는다.

원문 링크를 누르면 실제 저장 기록의 해당 부분으로 이동한다. Secret 검색 모드에는 AI 답변 동작을 제공하지 않는다. 단순 키 입력·제목 검색만으로 네트워크 요청을 하지 않는다.

### AI-01. 공식 Codex 경로

회사 ChatGPT Enterprise 계정으로 공식 Codex app-server에 로그인하고 기존 Codex 스킬을 활용한다. 작업별 스킬 선택과 프롬프트 설정을 제공한다. 기존 스킬 파일이나 전역 Codex 설정을 임의 수정하지 않는다.

모델·스킬·권한은 실제 설치 버전과 회사 정책에서 사용 가능한 것을 조회·검증한다. Enterprise를 일반 외부 앱 OAuth와 동일한 요금 모델로 가정하지 않는다. 인증·권한·한도 오류를 구분하고 개인 계정/유료 API로 자동 전환하지 않는다.

Secret은 제목을 포함하여 모든 AI 작업에서 제외한다. 일반 기록이 회사 AI로 전송되는 범위는 설정 화면에서 확인 가능하게 한다.

## 12. Secret — 최종 설계

### SEC-01. AI가 없는 표 기반 보관함

제목, 그룹, key/value 표로 직접 입력·수정한다. **Secret 입력·구조화·검색·복사·버전 관리에 AI를 사용하지 않는다.** 초기 논의의 로컬 LLM 또는 회사 AI 마스킹 전송은 폐기됐다.

제목과 그룹은 직접 작성·선택한다. 제목이 비어도 임시 제목을 붙여 저장 가능하게 하는 것을 제안 기본값으로 둔다.

### SEC-02. JSON과 문자열

본문을 항목 ID가 있는 JSON 구조로 직렬화한다. 자료형은 모두 문자열이다. `00123`, `true`, JSON처럼 보이는 문자열도 임의로 숫자·불리언·객체로 변환하지 않는다. 실제 저장 파일/DB에는 암호화된 본문을 보관한다.

항목 ID는 key 이름을 바꾸어도 유지한다. 동일 보관 항목 안에서 key 충돌은 저장 전 확인하며 자동으로 값 하나를 버리지 않는다.

### SEC-03. 저장 시 trim

key와 value는 저장 시 **앞뒤의 공백·탭·개행만 제거**한다. 내부 공백·탭·개행·대소문자·문자열은 보존한다. 표 입력, 붙여넣기, 새 저장, 수정 저장에 같은 규칙을 적용한다.

예:

```text
입력 key:   "  API_KEY  "
입력 value: "  abc 123  "
저장 key:   "API_KEY"
저장 value: "abc 123"
```

값 내부 Unicode 정규화나 URL 디코딩, 따옴표 삭제 등을 임의로 수행하지 않는다. 이 앱은 최종 요구에 따라 앞뒤 공백이 의미 있는 비밀값도 trim하는 제품이라는 점을 설정 도움말에 짧게 표시한다.

key가 trim 후 비어 있으면 사용하지 않는 `key1`, `key2` 등을 생성한다. 기존 `key1`을 임의로 덮어쓰지 않는다. 완전히 빈 새 행은 무시하는 것을 제안한다. 기존 value를 빈 문자열로 바꾸는 것과 행 삭제는 구분한다.

### SEC-04. 붙여넣기와 부분 수정

직접 표 입력이 기본이다. `A=B`, `A : B` 같은 여러 줄을 로컬에서 표로 나누는 보조 기능을 제공한다. 첫 유효 구분자 뒤의 내용은 전체 value로 보존한다. 구분자 해석이 불명확하면 행 전체를 value로 남기고 자동 key를 부여하여 미리보기에서 수정한다.

기존 항목 수정은 안정적인 row ID를 대상으로 한다. 입력하지 않은 다른 항목은 유지한다. 매 타이핑이 아닌 저장 단위로 새 버전을 만든다. trim 이후 실제 변경이 없으면 빈 버전을 만들지 않는 것을 제안한다.

전체 교체 전용 기능은 없다. 전체 변경이 필요하면 보관 항목을 삭제하고 새로 등록한다.

### SEC-05. 검색·복사·잠금

검색 핫키 → 제목 검색 → 항목 선택 → 필요 시 기기 인증 → key 목록 → key 선택 시 value 복사.

검색 모드의 선택은 복사이고 편집 화면의 셀 선택은 수정이다. value는 기본 가림이고 보기 동작을 따로 둔다. 이전 버전은 별도 이력 화면에서 명시적으로 선택한다.

반복 인증을 과도하게 요구하지 않는다. **제안 기본값:** 30분 미사용 후 잠금, 사용 중에는 갱신, 화면 잠금·앱 종료 시 잠금, 복사 후 2분이 지나도 같은 앱 복사 항목이 클립보드에 남아 있을 때만 삭제. 시간은 설정 가능하다.

다른 클립보드 내용은 지우지 않는다. 다른 앱의 클립보드 관리자나 이미 복사된 사본까지 제거한다고 보장하지 않는다.

### SEC-06. 휴지통·버전

보관 항목 전체 삭제는 현재 내용과 이전 버전을 함께 휴지통으로 이동한다. 일반 검색에서는 제외한다. 복원하면 같은 항목과 이력을 돌려놓는다. 영구 삭제는 별도 확인 후 현재 저장소의 해당 데이터와 이력을 제거한다.

표의 행 삭제는 보관 항목 자체의 삭제가 아니라 새 revision으로 기록한다. 이전 버전에서 행을 되살릴 수 있다.

과거 백업에 있는 사본은 영구 삭제와 별도로 관리한다. UI가 ‘모든 사본 완전 소거’를 보장하지 않는다.

### SEC-07. 보호 경계

실제 본문·이전 값·초안은 로컬 암호화한다. 제목 검색을 위한 최소 메타데이터는 별도 보관할 수 있으나 이것도 AI에서 제외한다. 비밀값을 로그, crash report, 임시 평문 파일, 일반 FTS, AI 스킬 작업 공간, clipboard history 자체 기능에 쌓지 않는다.

## 13. 백업과 복원

### BACKUP-01. 자동 홈 폴더

`~/<앱이름>/backups/`를 자동 생성한다. 사용자가 위치를 선택해야 시작하는 구조가 아니다. 실제 데이터 저장소와 백업 디렉터리는 분리한다.

백업 폴더 열기, 마지막 성공·실패 시각, 복원 기능을 제공한다. **제안 기본값:** 변경이 있을 때 일 단위 백업, 최근 30일 복원 지점 유지, 마이그레이션 직전 별도 복원 지점. 데이터 손실 없이 atomic하게 완료 상태를 표시한다.

### BACKUP-02. 포함과 제외

일반 기록, Task 이력·프로젝트·태그·계획, 프롬프트·설정, 리포트 버전·근거, 휴지통, 암호화된 Secret과 이전 버전을 포함한다. 검색 인덱스는 재생성 가능하다.

Codex OAuth 토큰·시스템 Keychain 값·임의의 회사 인증 파일은 백업에 덤프하지 않는다. 암호화 키가 없으면 Secret 백업을 복원할 수 없다는 한계를 숨기지 않는다.

첫 범위는 같은 Mac과 기존 Keychain을 보존한 복원이다. 다른 기기로의 복구 키 이관은 별도 선택 기능으로 둔다. 같은 디스크 백업은 기기 분실·디스크 고장 대책이 아니다.

### BACKUP-03. 복원

백업 형식·해시·스키마를 확인하고 복원 전 현재 데이터를 보존한다. 복원은 부분 실패로 원본을 파괴하지 않게 한다. Secret 키가 없거나 암호문이 손상됐으면 정확히 알리고 새 키로 기존 보관함을 덮어쓰지 않는다.

## 14. 향후 링크 읽기

### LINK-01. 현재

Task와 Memo의 URL 저장·열기만 지원해도 첫 버전을 사용할 수 있다. 원문을 읽지 않았다면 URL을 근거 첨부로만 쓰고 PR 내용·결과를 추측하지 않는다.

### LINK-02. 다음 단계

Task에 명시적으로 연결한 사내 GitHub PR과 회사 인증의 Atlassian Cloud Jira 이슈만 읽기 대상으로 한다. 한 Task에 여러 PR/이슈를 연결할 수 있다. Memo 링크, Confluence, 일반 웹 링크의 자동 내용 수집은 포함하지 않는다.

가져온 내용은 출처·가져온 시각·revision을 가진 외부 근거다. Task 상태를 자동 바꾸지 않는다. 읽기 실패·사내망 미접속이어도 앱 핵심 기능은 유지한다.

### LINK-03. 이후 쓰기

Jira 이슈를 Task로 연동하고 수정하는 기능은 별도 버전이다. 인증·필드 소유권·충돌·확인 UX를 추가 설계하기 전에는 첫 버전에 넣지 않는다.

## 15. 품질과 제안 기본값

오프라인에서도 입력·Task 상태 변경·원문 검색·Secret·복원은 작동해야 한다. AI나 연동 실패는 데이터를 잃는 이유가 될 수 없다. 한글·공백 프로젝트명·짧은 검색어·장문 기록을 검증한다.

성능 수치는 사용자 확정 요구가 아닌 검증 목표다. 5만 일반 기록의 테스트 데이터에서 입력창 준비와 저장은 체감 즉시, 원문 검색은 정상적인 길이의 검색어에서 대략 300ms 이내를 초기 목표로 측정한다. 장치·데이터·쿼리별 결과를 실제로 기록하며 미측정 수치를 달성했다고 하지 않는다.

UI는 Mac의 키보드·다크/라이트 모드·접근성 설정을 존중하는 네이티브 방향을 제안한다. 특정 OS 최소 버전, 앱 이름, 단축키 조합, 기술 라이브러리, 30분/2분/30일/월요일 09시 같은 값은 변경 가능한 **제안 기본값**이지 인터뷰에서 모두 확정한 것은 아니다.
