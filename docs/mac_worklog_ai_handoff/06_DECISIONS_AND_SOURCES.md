## 2. 폐기되거나 바뀐 설계

이 표는 과거 대화를 읽은 구현 AI가 오래된 선택으로 돌아가지 않게 하기 위한 것이다.

| 이전 논의 | 최종 해석 |
|---|---|
| Secret을 작은 로컬 LLM으로 구조화 | 폐기. 표 입력으로 직접 구조화 |
| 별도 로컬 모델 서버를 연결하는 방식 | 폐기. Secret용 모델 서버 의존성 없음 |
| 회사 AI에 Secret 원문을 보내기 | 폐기 |
| value를 가린 뒤 회사 AI에 Secret 구조화 요청 | 이 방식도 최종적으로 폐기. Secret AI 호출 자체가 없음 |
| 백업 위치를 사용자가 지정 | 홈 아래 앱 전용 backups 폴더 자동 생성 |
| 한 Task에 대표 프로젝트 하나만 | 여러 프로젝트와 선택적 프로젝트별 상태 |
| Task가 완료되면 과거 날짜도 완료로 표시 | 날짜별 실제 상태 이력과 확정 보고서 snapshot 유지 |
| 프로젝트/체크리스트가 모두 끝나면 전체 완료 | 전체 완료는 수동 확정 |
| 주간보고와 Weekly 리포트가 같은 문서 | 제출용 간단 보고와 상세 성과용 문서를 분리 |
| 월요일 최신 상태로 지난주 보고 | 일요일 종료 상태 기준 |
| 모든 예정 Task를 이번 주 예정으로 보고 | 사용자 확인한 이번 주 범위만 |
| GitHub·Jira·Confluence·Memo URL 전반 수집 | 후속에서도 Task의 PR/Jira만 |
| Secret 원문 공백을 항상 전부 보존 | 마지막 수정에 따라 key/value 앞뒤는 trim, 내부는 보존 |

## 4. 실제 구현에서 확인할 사항

이 항목들은 다시 제품 인터뷰를 시작할 이유가 아니다. 설치 환경을 확인해 처리한다.

- 실행 가능한 macOS·Xcode·Swift 버전과 배포 목표.
- 전역 핫키의 실제 등록 방식, 충돌, 필요한 권한.
- Codex 설치 경로·버전·현재 지원 프로토콜, 회사 workspace의 로컬 Codex 권한.
- 기존 스킬의 실제 위치·의존성·필요 권한과 안전한 보고 모드에서의 사용 가능 여부.
- Enterprise 실제 한도·과금 형태와 앱에 노출 가능한 정보 범위.
- SQLite 빌드의 FTS5/tokenizer 지원과 한국어 검색 결과.
- Keychain 인증·잠금 세션·백업 복원의 실제 동작.

확인 불가 항목은 Mock으로 분리하고 ‘미검증’을 표시한다. 사용자의 토큰을 요구하거나 보안 정책을 우회해서 확인하지 않는다.

## 5. 기술 자료 확인 노트

아래는 2026-10-01에 확인한 공식 문서다. 제품 결정의 출처는 사용자 인터뷰이며, 외부 자료는 기술 선택과 연결 경로를 검토하는 데만 사용했다. API·화면·회사 권한은 변할 수 있으므로 구현 시 다시 확인한다. 가격·사용량 숫자는 이 패키지에서 고정하지 않았다.

### [S1] OpenAI — Codex app-server

- 문서: https://developers.openai.com/codex/app-server/
- 확인 시 연결된 주소: https://learn.chatgpt.com/docs/app-server
- 사용 근거: 공식 로컬 프로토콜, 계정 로그인, 스킬 조회, 턴 실행, 제한된 읽기 범위.
- 주의: 단순 읽기 전용과 읽을 수 있는 경로 제한은 다르다. 실제 설치 버전의 스키마로 검증한다.

### [S2] OpenAI — Codex skills

- 문서: https://developers.openai.com/codex/skills/
- 확인 시 연결된 주소: https://learn.chatgpt.com/docs/build-skills
- 사용 근거: 기존 스킬을 발견·선택해 쓰는 통합 방향.
- 주의: 스킬과 의존 권한의 가용성은 환경별로 확인한다. 이 패키지는 기존 스킬을 복제하거나 전역 파일을 자동 수정하지 않는다.

### [S3] OpenAI Help — Using Codex with your ChatGPT plan

- 문서: https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan
- 사용 근거: ChatGPT 계정 로그인, Enterprise 관리 설정과 사용량/과금 확인 필요성.
- 주의: 모든 Enterprise 계약을 동일한 크레딧 차감 방식으로 단정하지 않는다. 회사의 사용 조건과 실제 허용 기능을 따른다.

### [S4] SQLite — FTS5

- 문서: https://sqlite.org/fts5.html
- 사용 근거: 로컬 전문 검색과 tokenizer·prefix·trigram 검토.
- 주의: 실제 배포 SQLite의 기능과 짧은 한글 검색은 별도 테스트한다.

### [S5] SQLite — Online Backup API

- 문서: https://sqlite.org/backup.html
- 사용 근거: 실행 중인 DB의 일관된 snapshot을 만드는 방식.
- 주의: 여러 DB와 설정 파일의 공통 일관성은 앱이 조정해야 한다.

### [S6] Apple — Keychain services / Keychain data protection

- API: https://developer.apple.com/documentation/security/keychain-services
- 보안 안내: https://support.apple.com/guide/security/keychain-data-protection-secb0694df1a/web
- 사용 근거: 암호화 키 보관의 플랫폼 기능 후보.
- 주의: 접근 제어·인증·동기화 여부는 macOS API와 실제 제품 요구에 맞춰 검증한다.

### [S7] Apple — CryptoKit AES.GCM

- API: https://developer.apple.com/documentation/cryptokit/aes/gcm
- 사용 근거: Secret JSON의 인증 암호화 구현 후보.
- 주의: 키·nonce·추가 인증 데이터·revision 관리는 구현과 테스트가 필요하다. 이 문서를 첨부했다는 사실만으로 안전한 앱이 완성되는 것은 아니다.

## 6. 제품 행동과 기술 검증을 혼동하지 말 것

‘회사 AI 사용’은 모든 회사 자료의 자동 수집 허가가 아니다. 이 앱은 사용자가 작성한 일반 기록과 후속으로 명시한 Task 링크만 다룬다. ‘로컬 Secret’도 같은 기기의 악성 프로그램·관리자 침해·클립보드 관리자까지 완전히 방어한다는 뜻은 아니다.

‘JSON 구조’는 평문 저장을 뜻하지 않고, ‘백업 있음’은 기기 자체 손실에서의 복구를 보장하지 않는다. ‘리포트에 출처 있음’은 외부 링크 본문을 실제로 읽었다는 뜻이 아니다. 앱 UI와 최종 구현 보고서에서 이 구분을 유지한다.
