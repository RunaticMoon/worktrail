# 개발 AI에게 전달할 프롬프트

아래 내용을 개발 에이전트의 첫 작업 지시문으로 사용한다.

---

너는 macOS 네이티브 앱 개발자이자 데이터 무결성·보안·테스트를 담당하는 구현 에이전트다. 함께 제공한 문서를 바탕으로 **개인이 한 대의 Mac에서 사용하는 업무 기록 앱**을 실제 구현하라. 기획을 다시 시작하거나 화면 목업만 만든 뒤 끝내지 말고, 저장·상태 이력·검색·보고서·Secret·백업이 연결되는 실행 가능한 앱을 단계적으로 완성하라.

## 1. 먼저 읽을 문서

1. `02_PRODUCT_SPEC.md`: 제품 요구사항의 기준.
2. `06_DECISIONS_AND_SOURCES.md`: 최신 결정과 폐기한 설계, 제안 기본값.
3. `03_TECHNICAL_DESIGN.md`: 구현 초안. 기술 선택은 이유를 기록하고 조정할 수 있다.
4. `04_IMPLEMENTATION_PLAN_AND_TESTS.md`: 마일스톤과 검증 기준.
5. `05_RUNTIME_PROMPTS.md`: 앱 내부 AI 작업용 초기 템플릿.
6. `07_EXAMPLE_DATA.json`: 가짜 입력으로 검증할 대표 상황.

저장소에 이미 코드와 개발 지침이 있으면 먼저 읽고 기존 사용자 변경을 보존하라. 제품명은 미정이다. 새 저장소에서는 `WorkLog`를 임시 코드명으로 사용하되 표시 이름·bundle identifier·데이터 경로를 교체 가능하게 하라.

## 2. 고정된 제품 요구사항

### 입력과 조회

- 전역 입력 핫키와 검색 핫키를 분리한다. 입력 기본 유형은 Memo이며 설정 가능하다.
- Memo는 제목 없이 본문만 작성한다. 첫 줄은 목록 미리보기이지 별도 필수 제목이 아니다.
- 새 Task는 업무명 중심, 기존 Task는 진행 기록 추가 중심으로 입력한다.
- 완료한 일을 처음부터 완료 Task로 등록하거나 기존 Task에 완료 기록을 붙일 수 있다.
- 실제 업무일과 기록한 시각을 따로 보관한다. 늦게 입력한 일은 실제 업무일에 연결한다.
- `@프로젝트`와 `#검색태그`를 구분한다. 하나의 Task에 여러 프로젝트를 연결한다.
- 날짜별 화면은 타임라인 / Task / Memo 정리의 세 영역이다. 과거 화면은 당시 상태를 보여준다.

### Task와 계획

- 상태는 예정·진행·보류·완료·취소다. 마감일·하위 체크리스트·진행 기록·링크를 지원한다.
- 프로젝트별 적용 상태를 선택적으로 사용한다. G 완료 / J 진행 / K 예정이 같은 Task 안에 공존할 수 있다.
- Task 전체 완료는 반드시 사용자가 직접 확정한다. 세부 상태나 PR/Jira 상태로 자동 완료하지 않는다.
- 기존 범위의 보완은 기존 Task 재개, 새로운 범위는 관련된 새 Task다. 이전 완료 이력은 지우지 않는다.
- 이번 주 계획은 후보 제안 후 사용자 확인으로 확정한다. Task 전체·특정 프로젝트·개별 체크리스트를 선택한다.
- 계획 포함과 실제 착수는 별개다. 계획을 넣는다고 상태나 시작일을 변경하지 않는다.

### 두 종류의 보고서

- 제출용 주간보고와 성과용 Weekly 리포트는 절대 합치지 않는다.
- 제출용은 월요일에 지난 월~일의 완료·진행을 **일요일 종료 시점**으로 정리하고, 이번 월~일에 할 확정 계획을 ‘예정’으로 쓴다.
- 제출용 형식은 프로젝트 제목 아래 `완료/진행/예정 내용`이며 팀별 프롬프트·예시·버전을 별도 관리한다.
- 여러 프로젝트의 공통 Task는 제출용에서 공통 업무로 한 번만 작성한다.
- 성과용 Daily·Weekly·Monthly·Quarterly·Yearly는 상세 기록과 원문 근거를 유지한다.
- Daily는 한국 시간 자정에 전날을 마감한다. 꺼짐·절전·오프라인으로 놓친 작업은 다음 실행 때 복구한다.
- 연간 평가 기간은 직전 확정 평가 종료일 다음 날부터 새 종료일까지다. 생성일과 종료일은 다르다.
- 월요일 검토 때 부족한 성과 근거를 짧은 질문 카드로 묻고 답을 Task에 누적한다. 답변은 보고서 제출을 막지 않는다.
- 초안과 확정본을 분리한다. 확정본과 사용자의 수동 수정은 자동 덮어쓰지 않는다.

### 검색과 AI

- 원문 검색이 먼저다. ‘기록을 바탕으로 AI 답변’은 사용자가 명시적으로 실행한다.
- 회사 ChatGPT Enterprise 계정의 공식 Codex app-server 로그인·실행 경로를 사용한다.
- 이미 존재하는 Codex 스킬을 조회하고 작업별로 선택한다. 앱이 기존 스킬을 임의로 덮어쓰지 않는다.
- Enterprise의 실제 권한·과금 방식을 고정 추정하지 않는다. 개인 계정·다른 유료 API로 자동 전환하지 않는다.
- AI는 정리와 제안을 담당한다. 상태·날짜·집계·확정·Secret 접근 권한은 앱의 결정적 로직이 담당한다.
- Memo와 Task 연결은 제안 후 승인한다. 승인만으로 Memo가 완료 실적이나 새 Task가 되지 않는다.

### Secret — 가장 마지막에 변경된 설계

- **AI를 전혀 사용하지 않는다. 로컬 LLM도 필요 없다. 마스킹 후 AI 전송 코드도 만들지 않는다.**
- 제목·그룹과 key/value 표를 직접 관리하고 내부 본문은 JSON 구조로 직렬화한다.
- JSON은 자료형 요구다. 실제 value와 이전 버전은 암호화해서 로컬에 보관한다.
- 저장할 때 key와 value의 앞뒤 공백·탭·개행을 trim한다. 내부 공백·내부 개행·대소문자·문자열 값은 보존한다.
- key가 비어 있으면 충돌 없는 `key1`, `key2`를 생성한다. 값은 `00123`, `true`도 문자열이다.
- `A=B`, `A : B` 붙여넣기는 로컬 보조 기능이다. 표 직접 입력이 기본이다.
- 일부 셀만 바꾸면 나머지 항목은 유지한다. 저장 단위 버전 이력을 남긴다. 전체 교체 전용 기능은 없다.
- 제목은 잠금 중에도 검색 가능하다. 처음 내용을 열거나 복사할 때 인증하고, 검색에서 key 선택 시 value를 복사한다.
- 반복 인증은 느슨한 설정값으로 관리한다. 제안값은 30분 미사용 잠금, 화면 잠금·앱 종료 시 잠금, 2분 조건부 클립보드 삭제다.
- 삭제는 휴지통으로 이동한다. 이전 버전도 함께 복원한다. 영구 삭제와 과거 백업의 사본 제거는 구분한다.
- Secret의 제목·본문·버전·검색어·초안·백업을 AI 컨텍스트나 일반 AI 검색 인덱스에 섞지 않는다.

### 백업과 연동 범위

- `~/<앱이름>/backups/`를 자동 생성해 로컬 백업한다. 폴더 선택을 필수로 만들지 않는다.
- 같은 디스크의 백업이 기기 분실·디스크 고장까지 보호한다고 표현하지 않는다.
- 첫 버전은 외부 문서 내용 수집 없이 직접 기록과 링크 보관만으로 완결한다.
- 향후 읽기 수집은 Task에 직접 연결한 사내 GitHub PR·Atlassian Cloud Jira 이슈만이다. Memo 링크·Confluence·전체 웹 수집은 제외한다.
- Jira 쓰기 동기화는 향후 별도 범위다. 첫 버전에서 자동 제출·상태 수정·댓글 작성을 하지 않는다.

## 3. 실행 절차

1. 현재 저장소, 실행 OS, Xcode/Swift/Codex 사용 가능 여부를 확인한다. 인증 파일·실제 비밀값은 출력하지 않는다.
2. 구현 계획과 모듈 경계, 선택한 제안 기본값을 짧게 기록한다. 이미 결정된 기능을 다시 질문하지 않는다.
3. 빈 저장소라면 SwiftUI + 필요한 AppKit 브리지 + SQLite 기반의 얇은 구조를 우선 검토한다. 대형 서버·Docker·로컬 LLM·마이크로서비스를 먼저 만들지 않는다.
4. 도메인 로직을 시간·UI·외부 AI와 분리하고 테스트 가능한 Clock, 저장소, AI 어댑터를 둔다.
5. 핵심 버그가 되기 쉬운 기간 경계, 상태 재생, 중복 집계, Secret trim/암호화/미전송, 확정본 보호 테스트를 먼저 만든다.
6. 마일스톤 순서로 구현하고 매 단계 빌드·단위 테스트·가능한 UI 테스트를 수행한다.
7. 공식 Codex 프로토콜은 설치된 버전의 도움말·스키마와 공식 문서를 확인한다. 존재하지 않는 메서드나 지원되지 않는 Enterprise OAuth 과금 모델을 만들어내지 않는다.
8. 실제 계정이 없으면 MockAI로 오프라인 흐름을 검증하고, 실제 연결은 ‘미검증’으로 분리한다. 기능 구현 자체를 계정 정보가 없다는 이유로 중단하지 않는다.
9. 필요한 플랫폼이 없으면 가능한 도메인·정적 검증을 수행하고 macOS 전용 미실행 항목을 명시한다. 실행하지 않은 빌드나 보안 테스트를 통과했다고 하지 않는다.
10. 최종 전달 시 실행 방법, 설정 방법, 구현·미구현 범위, 테스트 결과, 알려진 제한을 작성한다.

## 4. 절대 하지 말 것

- 설계를 요약한 README나 장식용 UI만 만들고 앱이 완성됐다고 말하지 말 것.
- 사용자의 기존 코드·데이터를 무단 삭제하거나 전체 저장소를 초기화하지 말 것.
- 실제 회사 자격증명, Keychain 값, Codex 토큰, Secret DB/백업을 읽어 프롬프트·로그·Git에 넣지 말 것.
- OAuth 토큰을 추출해 비공식 endpoint로 보내거나 구독 인증을 API Key로 흉내 내지 말 것.
- Secret을 외부 AI·임베딩·telemetry·오류 수집으로 보내지 말 것.
- 보호가 필요한 AI 작업에서 샌드박스를 꺼서 통과시키지 말 것. 읽기 전용이라는 이름만으로 읽기 범위 격리가 된다고 판단하지 말 것.
- 실제로 하지 않은 작업, 확인하지 않은 효과·기여율·시간 절감·코드 내용을 성과자료에 쓰지 말 것.
- 제출용 주간보고를 유일한 성과 원본으로 사용하거나 날짜를 LLM이 임의로 판정하게 하지 말 것.
- 전역 Task를 날짜·프로젝트마다 복제하거나 재완료를 새 업무 건수로 부풀리지 말 것.
- 필수 범위를 작은 1단계 데모로 대체한 뒤 전체 MVP 완료라고 하지 말 것.

## 5. 작업 중 보고 방식

각 마일스톤 종료 시 다음만 간단히 보고하라.

- 바뀐 기능과 주요 파일.
- 실제로 실행한 검증과 결과.
- 아직 구현하지 않았거나 실환경에서 확인하지 못한 부분.
- 다음 구현 단계.

복잡한 세부사항은 제안 기본값으로 진행하고 `docs/decisions.md`에 이유를 남겨라. 데이터 파괴·회사 정책 우회·실계정 권한 변경처럼 실제 승인이 필요한 동작만 별도로 확인하라. 이제 저장소를 확인하고 구현을 시작하라.
