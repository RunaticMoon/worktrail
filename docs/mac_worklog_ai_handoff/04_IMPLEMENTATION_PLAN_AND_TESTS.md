# 구현 순서와 인수 테스트

이 문서의 테스트는 **구현 AI가 수행할 검증 요구사항**이다. 문서 패키지를 생성한 시점에 Mac 앱이나 실제 계정을 테스트했다는 뜻이 아니다.

## 1. 개발 원칙

각 단계에서 실행 가능한 작은 흐름을 만들되, 일부 단계의 완료를 전체 MVP 완료라고 부르지 않는다. 첫 버전에서 외부 PR/Jira 본문 읽기만 후속으로 미룬다. Secret·주간보고·성과용 리포트·검색·백업 등 확정 범위를 생략하지 않는다.

기본 테스트는 가짜 데이터와 주입 가능한 Clock·MockAI·임시 DB·테스트용 Keychain 대체물로 실행한다. 실제 Mac의 전역 핫키·기기 인증·클립보드·Keychain·Codex 통합은 별도 실환경 검증으로 분리한다.

## 2. 마일스톤

| 단계 | 구현 결과 | 단계 완료 기준 |
|---|---|---|
| M0. 기반과 계약 | 저장소 확인, 환경 기록, 앱 골격, 도메인 모듈, 테스트 러너, migration 기반 | 빌드 가능 여부를 실제 확인하고 환경 제약을 기록. 날짜·상태·Secret 정규화의 실패 테스트 작성 |
| M1. 즉시 기록 | 입력/검색 핫키 분리, Memo 기본 설정, Memo·Task 원문 저장, 실제 업무일 | AI 없이 입력·종료·재시작·원문 보존. 새 완료 Task 등록 가능 |
| M2. 업무 흐름 | Task 상태 이력, 체크리스트, 다중 프로젝트, 프로젝트별 상태, 재개·연결, 주간 계획 | 부분 완료가 전체를 변경하지 않음. 계획 승인과 실제 상태가 독립 |
| M3. Secret | 표·JSON·trim·암호화·부분 수정·버전·검색·복사·잠금·휴지통 | 네트워크 0회로 전 기능 동작, 값 미노출·복원·수정 테스트 통과 |
| M4. 날짜와 검색 | 3열 날짜 화면, 현재/과거 상태, 일반 FTS·필터, 원문 근거 이동 | 한글·짧은 검색·늦은 입력·프로젝트 중복 회귀 통과 |
| M5. 백업 | 홈 폴더 자동 생성, snapshot·manifest·보존·복원·오류 표시 | 저장 중 일관된 백업, 손상·키 없음·복원 실패에서 기존 데이터 보존 |
| M6. 회사 AI | 공식 app-server 어댑터, 계정 확인, 기존 스킬 조회·선택, 최소 권한, MockAI | 프로토콜·취소·실패 처리 검증. 실제 계정은 가능할 때 별도 검증 |
| M7. 보고서 | 제출용 주간보고, 다섯 성과 리포트, 템플릿 버전, 질문 카드, Memo 연결 제안, 명시적 AI 답변 | 기간·스냅샷·확정본·출처·중복 검증 통과 |
| M8. 사용 준비 | 누락 작업 복구, 설정, 접근성, 성능, 설치/실행 안내, 최종 회귀 | 필수 인수 테스트 결과표와 미검증 목록 제공. 데이터 초기화 없이 업데이트 |

M6 전에 보고 UI는 MockAI와 앱의 결정적 사실 객체로 개발할 수 있다. M7까지 연결 후에만 전체 앱의 MVP를 완료했다고 한다.

후속 L1: Task의 GitHub PR·Jira 이슈 읽기. 후속 L2: 별도 설계한 Jira 쓰기 동기화. 어느 것도 M1~M8의 완료를 지연시키는 선행 조건이 아니다.

## 3. 사용자 여정 기반 필수 시연

### 흐름 A — 업무 중 기록

1. 다른 앱에서 입력 핫키를 누른다.
2. Memo 모드에 바로 본문을 쓰고 저장한다.
3. 다시 입력창을 열어 Task를 선택하고 새 진행 업무를 만든다.
4. 오후에 기존 Task를 찾아 확인 사항과 링크를 붙인다.
5. 완료된 업무를 새 완료 Task로 추가한다.
6. 오늘 화면의 타임라인·Task·Memo가 서로 다른 역할로 표시된다.
7. 검색 핫키로 원문을 바로 찾는다.

### 흐름 B — 여러 프로젝트의 공통 업무

1. Task A에 @G @J @K를 붙이고 프로젝트별 적용 관리를 켠다.
2. G 완료, J 진행, K 예정을 기록한다.
3. 전체 Task는 진행으로 남는다.
4. 이번 주 계획 후보에서 J 적용과 공통 체크리스트만 선택·확정한다.
5. 제출용 보고서에는 공통 업무로 한 번만 표현되고, 계획에 없는 K가 ‘예정’에 추가되지 않는다.
6. 이후 모든 부분이 완료돼도 전체 완료는 직접 누른다.

### 흐름 C — 월요일 보고와 성과 축적

1. 일요일 종료 상태로 지난주 보고 초안을 만든다.
2. 월요일 오전에 완료한 업무가 지난주 완료로 뒤바뀌지 않는지 확인한다.
3. 이번 주 계획을 후보에서 선택한다.
4. 성과 질문에 하나만 답하고 나머지는 건너뛴다.
5. 짧은 제출용 텍스트를 복사·확정한다.
6. 상세 Weekly에는 추가 답변과 원문 근거가 보인다.
7. 다음 날 늦은 기록을 추가해도 확정 문장이 바뀌지 않는다.

### 흐름 D — Secret

1. Secret 표에 key/value를 앞뒤 공백과 함께 넣는다.
2. 저장 후 다시 열어 trim과 내부 공백 보존을 확인한다.
3. 제목 검색 후 인증하고 key 선택으로 value를 복사한다.
4. API_KEY 행 하나만 수정하고 다른 행이 유지되는지 확인한다.
5. 이전 값을 이력에서 확인한다.
6. 전체 Secret을 휴지통에 넣고 복원한다.
7. AI를 비활성화·오프라인으로 두어도 모두 작동하는지 확인한다.

### 흐름 E — 백업과 복구

1. 백업 위치를 묻지 않고 홈 하위에 폴더가 만들어지는지 확인한다.
2. 일반 기록과 Secret 변경 후 백업을 실행한다.
3. 별도 테스트 경로로 복원하고 revision·계획·보고서 확정본을 비교한다.
4. 키 없는 환경에서 Secret 복원이 실패하는 이유를 정확히 안내하는지 확인한다.
5. 실패 과정에서 기존 보관함이 새 빈 보관함으로 덮어쓰이지 않아야 한다.

## 9. 대표 픽스처의 기대 결과

`07_EXAMPLE_DATA.json`에는 다중 프로젝트 Task A, 일요일과 월요일에 상태가 달라지는 Task B, 월요일에 뒤늦게 입력한 Task C, 계획 후보·확정 범위, 가짜 Secret trim 예시가 있다.

고정 시각을 사용해 다음을 검증한다.

- 2026-10-04 종료 시 A는 진행, G 완료/J 진행/K 예정.
- 2026-10-04 종료 시 B는 진행이며 10-05의 완료를 적용하지 않는다.
- C는 실제 업무일 10-02 완료로 조회되지만, 10-04에 확정해 둔 기존 보고 snapshot에는 존재하지 않을 수 있다. 10-05 생성본과 과거 확정본의 ‘그때 알던 정보’를 구분한다.
- 이번 주 계획에는 확인한 A/J·문서 checklist만 들어가고 후보 K는 들어가지 않는다.
- A의 프로젝트 연결 3개가 전체 Task count 3개를 만들지 않는다.
- Secret의 정규화된 값은 fixture의 expected와 일치하고 어떤 AI 입력 객체에도 들어가지 않는다.

## 10. Definition of Done

아래 조건을 만족해야 전체 MVP 완료라고 보고한다.

- 핵심 사용자 여정 A~E가 실제 저장소와 UI로 연결되어 있다.
- 필수 도메인·암호화·기간·스냅샷·trim·중복 집계 테스트가 실행됐고 결과가 제공된다.
- native UI/Keychain/핫키/Codex 실계정 테스트 중 미실행 항목을 정확히 표시한다.
- 실제 source가 없는 목업 화면·가짜 연결 성공을 실기능이라고 표시하지 않는다.
- 회사 AI가 없어도 로컬 기능을 쓸 수 있다.
- Secret 전체 경로에 AI·임베딩·평문 로그 전송이 없다.
- 백업과 복원을 실제 테스트 경로에서 검증한다.
- 설치·실행·Codex 경로 설정·스킬 선택·권한·알림·복원 설명이 있다.
- 기존 데이터 migration과 실패 롤백 또는 안전 중단 경로가 있다.
- 후속 링크 연동과 실제 미검증 사항을 현재 구현 범위와 구분한다.
